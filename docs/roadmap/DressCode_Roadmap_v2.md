## ЧАСТЬ 1 — БАГИ (исправить первыми)

### 1.1 «Дней: 1/31» в прогнозе прошлых месяцев

**Проблема:** При просмотре прошлого месяца (например, февраля) в карточке филиала отображается блок «Прогноз до конца месяца: 0Р, Дней: 1/31 · тренд (1 раб.дн.)». Прогноз для завершённого месяца бессмысленен и путает пользователя.

**Причина:** API (строка 578 Код.gs) правильно возвращает `forecast: null` для прошлых месяцев. Но фронтенд (renderFilials) рендерит блок прогноза всегда, не проверяя значение.

**Что делать:**
- В `renderFilials()` (index.html) добавить проверку: если `f.forecast === null` или месяц < текущего — не рендерить блок прогноза
- Для прошлых месяцев вместо прогноза показывать итоговую строку: «Итог месяца: X₽ (Y% плана)»

**Где менять:** index.html → функция `renderFilials`, блок где генерируется HTML прогноза

---

### 1.2 «На счетах: нет данных» постоянно висит в шапке

**Проблема:** В правом верхнем углу дашборда отображается плашка «На счетах: нет данных» с кнопкой обновления. Она видна всегда и на всех вкладках.

**Причина:** Функция `updateBalanceBadge()` пытается отобразить баланс, но данные не загружаются (возможно, API для балансов не реализован или не настроен).

**Что делать (два варианта):**
- Вариант А: Скрыть плашку, пока данные балансов не подключены — `display: none` для элемента бэйджа
- Вариант Б: Подключить реальные данные балансов из Google Sheets (лист "БАЛАНСЫ")

**Где менять:** index.html → CSS стили бэйджа / функция `updateBalanceBadge`

---

### 1.3 Можно выбрать будущие месяцы без данных

**Проблема:** Селектор месяцев (`bizMonthSelect`) показывает все 12 месяцев, включая апрель–декабрь 2026. При выборе будущего месяца — все филиалы показывают 0Р без объяснения.

**Что делать:**
- Ограничить максимальный месяц текущим (март 2026 = месяц 3)
- Либо при нулевых данных показывать сообщение: «Данные за этот месяц ещё не внесены»
- При загрузке страницы — отключить будущие опции через `disabled`

**Где менять:** index.html → генерация `<option>` для `bizMonthSelect`

---

### 1.4 Нет индикатора загрузки при смене месяца

**Проблема:** При переключении месяца данные подгружаются с API (2–5 секунд). Карточки просто исчезают, нет спиннера.

**Что делать:**
- При начале загрузки — показывать спиннер или текст «Загрузка данных...»
- При ошибке — показывать сообщение с кнопкой «Повторить»
- При успехе — плавно показать карточки

**Где менять:** index.html → функция `loadBranches()`, добавить состояния loading/error/success

---

### 1.5 🆕 NaN% в заголовках сводки

**Проблема:** В заголовках сводки по сети отображается NaN%. Это значит, что значение не передаётся или отсутствует — parseFloat возвращает NaN, который подставляется в шаблон без проверки.

**Что делать:**
- Найти все места, где формируется процент в заголовках (сводка по сети, карточки филиалов)
- Добавить проверку: если значение NaN или undefined — показывать «—» или «н/д» вместо «NaN%»
- Проверить, передаёт ли API корректные значения для процента от плана

**Где менять:** index.html → рендер сводки по сети, renderFilials, все места с `%` в шаблонах

---

### 1.6 🆕 Прибыль считать за минусом аренды

**Проблема:** Сейчас «прибыль» в дашборде не учитывает аренду. Каждый филиал имеет индивидуальную аренду, которая уже проставлена в таблице «Ателье 2026» в ячейке K9 каждого листа филиала.

**Что делать:**
- В Apps Script (Код.gs) → `handleGetBranches`: для каждого филиала читать значение аренды из ячейки K9 соответствующего листа
- Вычитать аренду из выручки при расчёте прибыли: `profit = revenue - rent`
- Передавать во фронт и аренду, и прибыль за минусом аренды
- На фронте в карточке филиала и сводке показывать прибыль = выручка − аренда

**Где менять:**
- Apps Script → Код.gs → `handleGetBranches` (добавить чтение K9 из листа каждого филиала)
- index.html → renderFilials, сводка по сети (использовать новое поле прибыли)

**Данные:** Таблица «Ателье 2026», каждый лист филиала (М16, Екатерининский 8 и т.д.), ячейка K9 — актуальная аренда

## ЧАСТЬ 2 — UX-УЛУЧШЕНИЯ

### 2.1 Мобильная адаптация (КРИТИЧЕСКИ ВАЖНО)

**Проблема:** В проекте 0 media queries. На телефоне (375px) всё мелко масштабируется. Карточки нечитаемые.

**Что делать — минимальная мобильная адаптация:**

```css
@media (max-width: 768px) {
  /* Навигация — иконки табов в горизонтальную полосу */
  /* Сводка — блоки в одну колонку */
  /* Карточки филиалов — полная ширина, увеличить шрифт */
  /* Аналитика — полноэкранный режим */
  /* Селектор месяца — увеличить размер для тапа */
}
```

**Где менять:** index.html → блок `<style>`, добавить media queries

---

### 2.2 🆕 Текст налезает на текст / графики перекрывают на мобильных

**Проблема:** На мобильных устройствах в модальном окне аналитики филиала текст налезает на текст, подписи графиков перекрывают друг друга. Видно на скриншоте (iPhone, 375px).

**Что делать:**
- В модальном окне аналитики: уменьшить шрифт подписей графиков или повернуть их
- Графики с барами: добавить горизонтальный скролл или уменьшить ширину баров
- Подписи осей: сократить (1.1K → 1.1K ok, но убрать перекрытие)
- Заголовки секций: проверить, что не обрезаются и не налезают
- Блоки «Средний чек» и «Прогноз» — в колонку на мобильных вместо двух в ряд

**Где менять:** index.html → CSS media queries для модального окна аналитики, графиков, карточек внутри модалки

### 2.3 Прогноз для прошлых месяцев → Итог месяца

**Проблема:** Для прошлых месяцев блок прогноза не несёт информации.

**Где менять:** index.html → renderFilials, блок прогноза

### 2.4 🆕 Заменить плашку «Химчистка» на «Средний чек» в шапке

**Проблема:** В шапке вкладки «Бизнес» отображаются три плашки: Ателье / Химчистка / Всего, и ниже: Клиенты / Прибыль / Прогноз. Плашка «Химчистка» неинформативна в текущем виде.

### 2.5 🆕 Крестик закрытия модального окна филиала (сверху справа)

**Проблема:** При нажатии на филиал открывается модальное окно с аналитикой. Чтобы закрыть его, нужно прокрутить до конца и нажать кнопку «Закрыть». Это неудобно, особенно на мобильных, где окно длинное.

**Что делать:**
- Добавить крупный крестик (✕) в правом верхнем углу модального окна
- Крестик должен быть фиксированным (position: sticky или fixed), чтобы всегда был виден
- Кнопку «Закрыть» внизу оставить как дополнительную
- Размер крестика: достаточно крупный для тапа на мобильных (минимум 44×44px)

**Где менять:** index.html → HTML/CSS модального окна аналитики филиала, JS-обработчик закрытия

## ЧАСТЬ 3 — ОПТИМИЗАЦИЯ ПРОИЗВОДИТЕЛЬНОСТИ

### 3.1 Оптимизация API: один getValues() вместо 30 getValue()

**Проблема:** 10 филиалов × 3 = 30 отдельных вызовов к Sheets API. Замедляет ответ до 3–5 секунд.

**Что делать:**
```javascript
var allData = sheet.getRange(1, col + 1, 260, 1).getValues();
// В цикле: allData[f.rowAtelie - 1][0] вместо sheet.getRange(row, col).getValue()
```

**Ожидаемое ускорение:** с 3–5 сек до менее 1 сек

**Где менять:** Apps Script → Код.gs → `handleGetBranches`, строки 560–570

### 3.2 Кэширование API-ответов в localStorage

**Проблема:** Каждое переключение месяца — полный запрос к Apps Script. Нет кэширования.

- Текущий месяц — TTL 5 минут
- Прошлые месяцы — TTL 1 час
- Кнопка ↻ — принудительное обновление

**Где менять:** index.html → функция `loadBranches`
